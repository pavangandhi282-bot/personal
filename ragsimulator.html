WHAT IS HAPPENING?

The RAG system first needs its own source of truth.

Before anyone asks a question, the system collects the information it may later need to search. In a real system, this could come from documents, databases, internal tools, APIs, websites, or other enterprise data sources.

WHY CHUNK?

Smaller pieces make retrieval more precise.

Instead of searching one enormous document, the system divides content into manageable chunks. Later, it can retrieve only the pieces that are relevant to the user's question.

EMBEDDINGS

Each chunk becomes a numerical representation of meaning.

An embedding model converts the text into a high-dimensional vector. Text with similar meaning tends to be placed closer together in this vector space, making semantic search possible.

SEMANTIC SEARCH

The system looks for chunks closest in meaning.

It does not necessarily need the exact same words. Semantic similarity allows a query such as “Where can I find product 9781?” to retrieve content that says “SKU 9781 is stored at Rack B17.”

Retriever Decision

Context window
Retriever

Instead of giving the LLM the entire warehouse database, RAG gives it only the few chunks most relevant to this question.

TOP N

Only the most useful context moves forward.

The retriever ranks matching chunks and selects a limited number of the highest-quality results. This is commonly called Top-K or Top-N retrieval.

AUGMENTATION

This is where the “A” in RAG happens.

The original user question is augmented with the relevant information retrieved from the knowledge base. The LLM now receives both the question and supporting context.

THE KEY IDEA

RAG = Retrieval + Augmentation + Generation.

The model did not need to memorize the warehouse database. The system retrieved relevant company information first and then used an LLM to generate a natural-language answer from that information.
